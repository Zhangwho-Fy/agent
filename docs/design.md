# Agent 设计文档

> 本文是**规划层**：做什么、不做什么、分几期、怎么验收。
> 技术细节见 [detailed-design.md](./detailed-design.md)，面试考点见 [knowledge.md](./knowledge.md)。
>
> 变更：v0.4 编排层改用 **LangGraph**（行业标准栈），自研范围收敛到框架**不覆盖**的语义层；
> C++ 从必做项降为可选加分项。

## 1. 目标与非目标

### 目标

1. **代码库助手（主场景）**：在本地仓库上读代码、跑命令、改文件，闭环解决真实任务。
2. **聊天（兼有）**：同一个内核支持纯对话模式（`profile=chat`）。
3. **"部分生产可用"的证据链**：可持久化、可恢复、可重放、可评测，且失败模式有文档。

### 非目标

- **不自研编排引擎**——编排用 LangGraph，这是行业标准，自研只是重造轮子
- 不做多 Agent 编排框架、不做多租户 / 云部署
- 不做桌面端、移动端客户端
- 不做自己的模型训练或本地推理
- C++ 不是必做项（见第 6 节）

## 2. 架构概览

```
   CLI（瘦客户端）
        │
        ▼
   agent serve（本地长驻进程）
      ├─ server:      HTTP + SSE（对外契约）
      ├─ graph:       LangGraph 编排（状态 / 条件边 / checkpointer / interrupt）
      ├─ reliability: 事件日志、幂等、恢复（框架不覆盖的部分）
      ├─ tools:       执行 + 审批策略 + 沙箱
      ├─ retrieval:   代码检索（用 LangChain 组件）
      ├─ models:      LangChain 模型适配（ChatDeepSeek）+ 录放包装
      └─ store:       SQLite：对外事件流的事实源
              │
              └──> 本地仓库 / git / 测试 / 编译器
                   └── C++ 工具（可选，可降级）
```

### 三条不变量

1. **任务在服务端执行，客户端只是订阅者。** 客户端断线、退出不影响任务推进，重连后按 seq 补齐。
2. **工具只在有仓库的那台机器上执行**，且受工作区边界与审批策略约束。
3. **模型调用永远经过可替换的适配层**：线上走真实模型，测试走回放，CI 不需要密钥。

### 分工要点：框架负责什么，我们负责什么

| 层 | 谁负责 |
| --- | --- |
| 编排（状态机、条件边、检查点、人工介入、流式模式） | **LangGraph** |
| 模型适配、消息类型、工具 schema、检索组件、MCP 适配 | **LangChain** |
| 事件日志与对外契约、幂等、SSE 续传、崩溃恢复、token 记账 | 自研 |
| 沙箱与工作区边界、三级审批与默认值、输出截断、进程组超时 | 自研 |
| 录放、评测集、检索指标、CI | 自研 |

## 3. 里程碑

| 阶段 | 交付物 | 结束时能演示什么 |
| --- | --- | --- |
| 1. 最小闭环 | LangGraph 最小图 + 3 个工具 + 终端流式输出 | 让它读文件/跑命令回答问题 |
| 2. 可靠性层 | 事件日志持久化、幂等键、崩溃恢复 | `kill -9` 后重启，会话还在、能续跑 |
| 3. 工程化 | 录放、golden 评测集、CI | 不花一分钱跑回归 |
| 4. 服务化 | HTTP + SSE + CLI、协议冻结 | `curl` 走完一次会话，断线能续传 |
| 5. 检索（RAG） | LangChain 组件 + 自己的混合检索与评测 | 给出 recall@5 对比数据 |
| 6. 扩展 | MCP client（适配器）、**可选** C++ 工具 | 接第三方工具；C++ 缺失时自动降级 |

## 4. 验收标准

### 阶段验收

1. **最小闭环**：一条命令让它回答"`xxx.py` 里那个函数做了什么"，终端可见流式输出与工具调用；工具报错能被模型看到并自我纠正一次。
2. **可靠性层**：任务跑到一半 `kill -9`，重启后历史完整；`agent replay <trace>` 能按顺序还原全部事件，**不调用模型**。
3. **工程化**：`pytest` 全绿；`pytest eval` 输出 golden 集通过率；**不设置 API key 也能跑**（回放）；CI 有绿色构建。
4. **服务化**：只用 `curl` 走完"建会话 → 发消息 → SSE 收流 → 审批一次写操作 → 拿结果"；断线重连按 `Last-Event-ID` 补齐不丢不重；同一条消息发两次不重复执行工具。
5. **检索**：recall@5 / MRR 的实测对比写进 README。
6. **扩展**：接一个现成 MCP server 当工具源；C++ 不启动时自动降级且功能不受影响。

### 项目终验（面试现场能当场演）

1. 真实任务端到端跑通（真实仓库、真实修改、真实测试通过），全程可回放。
2. 故障注入：`kill -9`、断网、工具超时、审批超时各来一次，讲清各自的表现。
3. `agent replay` 离线还原历史会话。
4. 讲清威胁模型：哪些命令会被拒绝、密钥为什么不在客户端、工具输出为什么必须截断。

## 5. 分工与协作方式

- **[我]**：框架接线、可靠性层、store、server、测试、CLI、检索、文档。
- **[你]**：核心工具的边界（`shell_exec` 的命令与截断策略）、评测任务设计、每阶段 review。
- 每个小步：先讲设计意图与涉及的知识点（用 C++ 对照），再给代码，讲完你 review。

## 6. C++ 的位置：可选加分项

**结论：不是必需的。** 编排与模型层都由 Python 生态承担，C++ 在这里只能做两件事：性能热点（仓库扫描、语法解析）或演示跨语言边界。

- 形态：**独立进程 + CLI 接口**（被 Python 当工具调用），不引入 pybind11 的 ABI 复杂度
- 硬性要求：**必须可降级**——C++ 不存在时回落到纯 Python 实现，演示不押在它身上
- 何时做：阶段 1~5 全部完成之后，有时间再上；不做不影响项目成立
- 面试价值：能讲"为什么把这块放到进程边界外"就有价值；只写个 Hello World 则没有
