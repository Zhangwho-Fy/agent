# 写设计文档

## 读者与目标

读者是三个月后的自己，或者换一台机器接手的人。目标：他读完能知道**为什么这么做**，
以及**为什么没做另一种**。

## 核心原则

1. **决策 + 理由 + 不做什么**，三件缺一不可。只有结论没有理由的文档，下一个人会当它不存在。
2. **写清边界**：哪些归这一节、哪些归别处（给链接），避免两处互相矛盾。
3. **用表格列取舍**（做法 / 取舍 / 理由），比大段文字好查。
4. **决策编号**（D1、D2…）并且能被别的章节引用；改动旧决策时写"修订 Dx"，不要偷偷改。
5. **留一节"未决"**：把"还不知道"和"待实测"写下来，比假装定了更有用。

## 结构模板

- 文首：本文管什么、与其它文档的关系、状态（哪些已定稿）
- 背景与目标（一句话能说清）
- 设计正文（分层、表格、示例）
- 落点（文件清单）与验收（测试清单，断言要能被机器检查）
- 决策记录表
- 未决

## 禁止清单

- 不写没有理由的决策。
- 不把待办和设计混在一起——待办进任务清单，不进决策表。
- 不写"应该""可能"这种模棱两可的结论：要么定下来，要么进未决。
- 不复制代码细节：文档说"做什么、为什么"，实现看代码。

## 收尾

写完检查一遍：每条决策是不是都能回答"那为什么不选另一种？"。
