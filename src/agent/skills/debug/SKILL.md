# 排障

## 核心原则

1. **先复现再猜**：能跑就跑一次，拿到真实报错；跑不了就先用工具把缺的信息找齐。
2. **一次只改一个变量**：同时改三处，就算好了也不知道是哪处起的作用。
3. **先定位再修**：说得出"因为 X 所以 Y"再动手；说不清就继续查。
4. **修完必须验证**：跑原来的复现命令，最好再跑一次相关测试。
5. **报错是信息**：先读完（路径？权限？版本？），不要原样重试同一个命令。

## 流程

1. **复现**：拿到命令 + 完整报错（不要只看最后一行）。
2. **收缩**：二分——注释掉一半、缩小输入、换一个最小例子。
3. **定位**：看最近改动（`git diff` / `git log`）、读关键路径、必要时加定点输出。
4. **修**：最小改动。
5. **验证**：复现命令 + 相关测试，顺手说清根因。

## 禁止清单

- 不要在没复现的情况下声称修好了。
- 不要为了"看着像"而改代码。
- 不要用满屏 print 代替读代码——先读，再定点加。
- 不要顺手改无关文件。

## 输出

根因一句话 + 证据（命令 / 输出 / 行号）+ 改了什么 + 怎么验证的。
如果查到这里仍然没定位，直接说清"已经排除了什么、还差什么信息"，不要硬给一个猜测。
